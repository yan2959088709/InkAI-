# 实施计划：阶段二到四详细规划

## 决策总结

基于项目需求（长篇小说撰写），已做出以下决策：

1. ✅ **嵌入模型系统**: 实现完整的嵌入模型和RAG系统
2. ✅ **核心知识库**: 实现核心知识库的完整使用（双层知识库，支持动态更新）
3. ✅ **12个一致性Agent**: 集成到工作流中
4. ✅ **性能优化模块**: 真正集成到工作流中

## 实施原则

### 核心原则
1. **测试驱动**: 每一步都要测试，测试通过才算完成
2. **双层知识库必须**: 核心知识库 + 动态知识库，必须支持动态更新
3. **面向长篇小说**: 所有设计都要考虑长篇小说的特点（长文本、多章节、一致性要求高）

### 开发流程
```
设计 → 实现 → 单元测试 → 集成测试 → 功能测试 → 性能测试 → 文档更新 → 完成
```

## 阶段二：核心知识库实现（优先级最高）

### 为什么先做核心知识库？
- 核心知识库是双层知识库的基础
- 其他功能（嵌入模型、一致性检查）都依赖知识库
- 必须先建立稳定的知识库架构

### 2.1 核心知识库架构设计

#### 2.1.1 设计目标
- ✅ 双层架构：核心知识库（静态）+ 动态知识库（动态）
- ✅ 支持动态更新：随着章节推进自动更新
- ✅ 面向长篇小说：支持多章节、长文本、复杂关系

#### 2.1.2 架构设计
```
CoreKnowledgeManager (核心知识库)
├── 人物基础档案（静态）
├── 世界观设定（静态）
├── 故事主题（静态）
└── 基础规则（静态）

DynamicKnowledgeManager (动态知识库)
├── 人物发展轨迹（动态更新）
├── 情节时间线（动态更新）
├── 伏笔追踪（动态更新）
├── 世界观变化（动态更新）
├── 章节摘要（动态更新）
└── 关系发展（动态更新）

IntelligentContextSelector (智能上下文选择器)
├── 从核心知识库选择
├── 从动态知识库选择
└── 整合并压缩上下文
```
